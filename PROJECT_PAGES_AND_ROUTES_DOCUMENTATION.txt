1. PROJECT OVERVIEW & ARCHITECTURE
================================================================================
Indianiiot is an enterprise-grade Industrial IoT (IIoT) SaaS platform engineered 
to monitor, control, and visualize real-time hardware telemetry from microcontrollers 
(such as ESP32, ESP8266, Arduino, STM32, and Raspberry Pi) across diverse 
industrial domains (Gas Detection, Ambient Light & Actuation, Indoor Air Quality, 
and Schneider Electric Energy Metering).

Platform Key Technical Features:
- Real-Time Hardware Telemetry: Ingests sensor data at sub-second to 5s intervals.
- Plan-Based Device Quota Enforcement: Free (2 nodes), Starter (5 nodes), 
  Professional (15 nodes), Enterprise (100+ nodes).
- Automated Edge Actuation: Bidirectional GPIO control for microcontrollers to toggle 
  relays and smart bulbs dynamically based on sensor thresholds or user clicks.
- PayU Gateway Integration: Production-grade checkout with server-side SHA-512 
  hash calculation and verification.
- Automated Subscription Expiry Alerts: Daily cron background job (APScheduler) 
  checking expiring subscriptions and sending email notices via Brevo.
- Interactive Hardware Simulators: In-browser LCD screen simulation for LDR nodes, 
  MQ Gas nodes, and Schneider EM6400-series 3-phase digital energy meters.

PAGE 1: LOGIN PAGE
--------------------------------------------------------------------------------
- Component File : client/src/pages/Login.jsx
- URL Route      : /login
- Access Control : Public (Unauthenticated users)
- Purpose        : User login via email/password credentials or Google SSO.

- Functionality & How It Works:
  1. UI Design: Neo-glassmorphic login card over a dark ambient backdrop featuring 
     custom input fields for Email Address and Password with interactive show/hide 
     password visibility toggle.
  2. Form Submission: Collects credentials and calls the `login(email, password)` 
     method provided by `AuthContext.jsx`. Sends HTTP POST request to backend route 
     `/api/v1/auth/login`. Upon success, stores JWT bearer token in localStorage/
     sessionStorage and navigates to `/`.
  3. Google OAuth Single Sign-On (SSO): Initializes Google Identity Services API 
     (`window.google.accounts.id`) using `VITE_GOOGLE_CLIENT_ID`. Displays Google 
     One-Tap / standard SSO prompt. Transmits Google JWT credential to backend endpoint 
     `/api/v1/auth/google` for verification and account setup.
  4. Error Handling: Displays smooth animated alert banners for invalid credentials, 
     missing fields, or server connection timeouts. Includes a rate-limiter check 
     preventing brute-force attempts (30 requests/60s).

4. DETAILED BACKEND ROUTER & API ENDPOINTS CATALOG

--------------------------------------------------------------------------------
AUTHENTICATION ROUTER (server/app/routers/auth.py)
--------------------------------------------------------------------------------
1. POST /api/v1/auth/register
   - Description: Registers a new user account.
   - Request Body: `UserCreate` (email, password, full_name)
   - Functionality: Hashes password with bcrypt, creates User in DB (default plan='starter', 
     status='active', currency='INR'), dispatches Brevo welcome email.
   - Response: JSON user object representation.

2. POST /api/v1/auth/login
   - Description: Authenticates user credentials and issues JWT token.
   - Request Body: OAuth2Form (username=email, password=password)
   - Functionality: Verifies bcrypt password hash. Generates JWT access token with 
     expiry time.
   - Response: `{"access_token": "...", "token_type": "bearer"}`

3. POST /api/v1/auth/google
   - Description: Authenticates or registers users via Google OAuth SSO.
   - Request Body: `{"token": "GOOGLE_ID_TOKEN"}`
   - Functionality: Verifies Google token using Google Auth library. Looks up user by 
     google_id or email. Creates user if new. Generates JWT access token.
   - Response: `{"access_token": "...", "token_type": "bearer"}`

--------------------------------------------------------------------------------
DEVICE MANAGEMENT ROUTER (server/app/routers/devices.py)
--------------------------------------------------------------------------------
1. GET /api/v1/devices/
   - Description: Retrieves all devices belonging to the logged-in user.
   - Auth Required: JWT Bearer Token
   - Functionality: Queries DB. Calculates dynamic `is_online` boolean based on whether 
     `last_seen` timestamp is within the last 15 seconds.

2. GET /api/v1/devices/limit-info
   - Description: Returns plan node limit and used device count for the user.
   - Auth Required: JWT Bearer Token
   - Response: `{"plan": "starter", "limit": 5, "used": 2, "remaining": 3, "at_limit": false}`

3. GET /api/v1/devices/{device_id}
   - Description: Retrieves metadata for a specific device by ID.

4. POST /api/v1/devices/
   - Description: Registers a new device node.
   - Request Body: `DeviceCreate` (device_id, device_type)
   - Functionality: Checks user's plan quota. If under limit, creates Device record, 
     generates unique hex `device_token`.

5. DELETE /api/v1/devices/{device_id}
   - Description: Deletes a device and all associated sensor readings from DB.

--------------------------------------------------------------------------------
DATA INGESTION & READINGS ROUTER (server/app/routers/data.py)
--------------------------------------------------------------------------------
1. POST /api/v1/data/ingest
   - Description: High-speed edge ingestion endpoint for microcontrollers.
   - Header Auth: `X-Device-Token: <token>`
   - Request Body: `SensorDataIngest` (gas, temp, humidity, heat_index, iaq, co2, tvoc, 
     pm25, pm10, kWh, kW, volts, amps)
   - Functionality: Validates device token, updates device `last_seen` timestamp, 
     stores reading record in `sensor_readings` table.

2. GET /api/v1/devices/{device_id}/readings?limit=20
   - Description: Retrieves chronological historical sensor readings for a device.

--------------------------------------------------------------------------------
LDR & GPIO ACTUATOR ROUTER (server/app/routers/ldr.py)
--------------------------------------------------------------------------------
1. POST /api/v1/ldr/ingest
   - Description: Ingestion endpoint for LDR sensor nodes.
   - Header Auth: `X-Device-Token: <token>`
   - Request Body: `LDRDataIngest` (analog_value, voltage, lux)
   - Functionality: Saves LDR reading, updates `last_seen`, returns list of registered 
     GPIO outputs with current `is_active` state so microcontrollers can toggle relays.

2. GET /api/v1/ldr/{device_id}/readings?limit=20
   - Description: Retrieves historical LDR light intensity readings.

3. GET /api/v1/ldr/{device_id}/outputs
   - Description: Retrieves registered GPIO actuator output pins for a device.

4. POST /api/v1/ldr/{device_id}/outputs
   - Description: Registers a new GPIO output pin actuator (e.g. gpio_pin=18).

5. PUT /api/v1/ldr/outputs/{output_id}
   - Description: Toggles or updates `is_active` status for a GPIO output pin.

--------------------------------------------------------------------------------
PAYMENT GATEWAY ROUTER (server/app/routers/payment.py)
--------------------------------------------------------------------------------
1. POST /api/v1/payment/initiate
   - Description: Initiates a PayU payment checkout session.
   - Auth Required: JWT Bearer Token
   - Request Body: `{"plan_id": "professional", "currency": "INR"}`
   - Functionality: Calculates amount based on plan & currency. Generates unique `txnid`. 
     Computes SHA-512 hash (`sha512(key|txnid|amount|productinfo|firstname|email|...|salt)`). 
     Returns PayU checkout form parameters and action URL.

2. POST /api/v1/payment/success
   - Description: PayU HTTP POST callback for successful transaction.
   - Functionality: Validates PayU reverse SHA-512 hash (`sha512(salt|status|...|key)`). 
     Updates user subscription plan, status, currency, and expiry (30 days from now). 
     Logs record in `payments` table. Dispatches confirmation receipt email via Brevo. 
     Returns HTML response auto-redirecting frontend browser to `/payment/success?txnid=...`.

3. POST /api/v1/payment/failure
   - Description: PayU HTTP POST callback for failed/declined transaction.
   - Functionality: Logs failure event. Returns HTML response auto-redirecting browser 
     to `/payment/failure?txnid=...&reason=...`.

--------------------------------------------------------------------------------
USER PROFILE ROUTER (server/app/routers/users.py)
--------------------------------------------------------------------------------
1. GET /api/v1/users/me
   - Description: Returns current user's profile, preferences JSON, and subscription status.

2. PUT /api/v1/users/me
   - Description: Updates profile info (`full_name`, `phone_number`, `preferences` JSON).

3. PUT /api/v1/users/me/subscription
   - Description: Updates subscription details or cancels active subscription (downgrades to 'free').

--------------------------------------------------------------------------------
BACKGROUND JOBS & SCHEDULER (server/app/routers/jobs.py & main.py)
--------------------------------------------------------------------------------
- APScheduler Background Task: Runs daily at 00:00 UTC (`run_daily_expiry_check`). 
  Queries users with active paid subscriptions whose `subscription_expiry` is 7 days away. 
  Dispatches warning emails via Brevo alerting users to renew their plan.

5. DATABASE SCHEMA & DATA MODELS INTERACTION
================================================================================

1. `users` Table:
   - `id` (INTEGER PRIMARY KEY)
   - `email` (VARCHAR UNIQUE)
   - `hashed_password` (VARCHAR)
   - `full_name` (VARCHAR)
   - `phone_number` (VARCHAR)
   - `subscription_plan` (VARCHAR DEFAULT 'starter')
   - `subscription_status` (VARCHAR DEFAULT 'active')
   - `subscription_currency` (VARCHAR DEFAULT 'INR')
   - `subscription_expiry` (TIMESTAMP)
   - `preferences` (JSON / TEXT) - Stores custom UI sensor icon preferences
   - `google_id` (VARCHAR)
   - `is_admin` (BOOLEAN DEFAULT FALSE)
   - `created_at` (TIMESTAMP)

2. `devices` Table:
   - `id` (INTEGER PRIMARY KEY)
   - `device_id` (VARCHAR UNIQUE) - User-assigned identifier (e.g. ESP32_ALPHA)
   - `device_token` (VARCHAR UNIQUE) - Secret key for microcontroller API authentication

6. SECURITY, RATE LIMITING & ERROR HANDLING
================================================================================

1. Rate Limiting Middleware (`RateLimitMiddleware` in `server/app/main.py`):
   - Sliding Window In-Memory Rate Limiter enforced on authentication & edge ingestion routes.
   - Limit: Maximum 30 requests per 60-second window per client IP address.
   - Throttled Paths: `/auth/login`, `/auth/register`, `/auth/google`, `/api/v1/ingest`.
   - Returns HTTP 429 Too Many Requests when threshold is exceeded.

2. CORS Configuration:
   - Configured dynamically to allow localhost development ports (5173, 3000, 4173, 8000), 
     LAN IP addresses, and production domains (`indianiiot.com`, `mq-gas-censor-tronix.pages.dev`).

3. PayU SHA-512 Security:
   - All payment requests and callbacks use SHA-512 hashing with secret salt keys stored 
     securely in server environment variables (`PAYU_MERCHANT_KEY`, `PAYU_MERCHANT_SALT`), 
     preventing payment tampering or unauthorized plan escalations.
